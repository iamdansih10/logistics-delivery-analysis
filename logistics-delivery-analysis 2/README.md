# Last-Mile Delivery Analysis (Logistics Data Analyst Internship, Week 1)

A small project I built for the strategic planning and data exploration task
of my Logistics Data Analyst internship. The idea: take a realistic last-mile
delivery problem, define the KPIs that matter, and show how Python can answer
the questions a logistics team keeps running into.

> The dataset is **simulated**. It's generated by `src/generate_data.py` so
> the project runs anywhere, but it mimics real patterns (distance, rain and
> rush hour slow deliveries down, heavier loads cost more).

## What's inside

| File | What it does |
|------|--------------|
| `src/generate_data.py` | Creates 2,000 sample deliveries across 5 city zones |
| `src/analysis.py` | Cleans data, computes KPIs, draws charts, fits a delivery-time model, clusters orders, and runs a route-ordering demo |
| `data/deliveries.csv` | The generated dataset |
| `outputs/` | Charts, KPI tables and `results.json` |

## Run it

```bash
pip install -r requirements.txt
python src/generate_data.py
python src/analysis.py
```

## KPIs tracked

1. On-time delivery rate
2. Average delivery time (minutes)
3. Cost per delivery and cost per km
4. Stock-out rate

## Headline findings

- On-time rate is about 66%; rush-hour orders drop to roughly 47%.
- Rain adds about 9 minutes to a delivery.
- A simple linear model predicts delivery time with R² ≈ 0.91 (MAE ≈ 4.8 min).
- Ordering stops with a nearest-neighbour rule cut a 10-stop route by around 40% in the demo.
